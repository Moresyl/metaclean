# MetaClean 文档导航

这里按“使用者需要什么证据”组织文档，而不是按历史提交顺序堆放文件。

| 文档 | 读者 | 用途 |
| --- | --- | --- |
| [`PLAN.md`](PLAN.md) | 维护者、评审者 | 当前事实、已验证能力、风险和后续路线 |
| [`../README.md`](../README.md) | 用户、贡献者 | 产品能力、安装、构建和使用边界 |
| [`../README.zh-CN.md`](../README.zh-CN.md) | 中文用户 | 中文产品说明和支持范围 |
| [`../SUPPORT_POLICY.md`](../SUPPORT_POLICY.md) | 安全/格式维护者 | 每类格式的安全门槛、嵌套边界和拒绝策略 |
| [`../SECURITY.md`](../SECURITY.md) | 安全研究者 | 漏洞报告、更新信任根和分发边界 |
| [`../VALIDATION.md`](../VALIDATION.md) | 发布评审者 | 测试、构建、审计、E2E 和外部验证限制 |
| [`../COMPETITIVE_AUDIT.md`](../COMPETITIVE_AUDIT.md) | 产品/工程评审者 | 基于源码和测试证据的竞品差距记录 |
| [`../DESIGN.md`](../DESIGN.md) | UI 维护者 | 设计 tokens、信息层级、可访问性和禁止回退项 |
| [`../CHANGELOG.md`](../CHANGELOG.md) | 所有用户 | 版本变更、修复和工程维护记录 |
| [`../CONTRIBUTING.md`](../CONTRIBUTING.md) | 贡献者 | 代码、测试和安全贡献规则 |

## 文档规则

- 先写当前事实，再写计划；不要把未验证假设写成完成状态。
- 每个数字必须能追溯到源码或门禁输出。
- 历史版本可以保留历史数字，但必须放在对应版本章节，不得冒充当前能力。
- 涉及用户文件、更新签名、权限或格式解析的说明，必须同时写出拒绝边界。
- “跨平台支持”要区分代码支持、CI 验证、实机验证和签名/公证状态。
